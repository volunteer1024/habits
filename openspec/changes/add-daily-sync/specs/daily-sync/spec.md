## Purpose

把本机完整打卡备份每个本地自然日最多成功上传一次到用户指定的接收服务，失败时保留本地数据并允许稍后重试。

## ADDED Requirements

### Requirement: 已配置地址时每个自然日最多成功上传一次

系统 MUST 在应用加载完成时，以及页面从隐藏变为可见时，检查是否需要同步。同步地址来自用户在「我的」页保存的地址；若用户尚未保存，则使用构建时配置的默认地址。两者都为空时，系统 MUST NOT 发出同步请求。若最近一次成功同步的本地自然日等于当前本地自然日，系统 MUST NOT 再发出请求。成功后系统 MUST 记住该本地自然日。自动检查成功时 MUST 只给出不打断操作的弱提示。

#### Scenario: 当天第一次打开会上传

- **WHEN** 已配置同步地址，且今天还没有成功同步
- **THEN** 系统上传一份当前数据的完整备份
- **AND** 记下今天已成功同步

#### Scenario: 同一天再次打开不再请求

- **WHEN** 今天已经成功同步过，用户再次打开应用或把页面切回前台
- **THEN** 系统不向接收服务发请求

#### Scenario: 没有地址就跳过

- **WHEN** 用户没有保存同步地址，且没有默认地址
- **THEN** 系统不发请求
- **AND** 本地打卡数据保持不变

### Requirement: 上传内容与导出备份是同一份结构

上传正文 MUST 包含与导出文件相同的备份信封：模式版本、导出时间和全部已持久化的领域数据。正文 MUST 另含稳定的本机标识，且该标识在同一浏览器中重复使用。上传 MUST NOT 改写 `checkin:v1` 里的领域数据，也 MUST NOT 把同步地址、本机标识或最近成功日写进导出文件。

#### Scenario: 成功请求带完整备份

- **WHEN** 系统执行一次同步
- **THEN** 请求正文含模式版本、导出时间、当前任务、打卡、坏习惯、日志、奖励、兑换、积分流水和结算
- **AND** 请求正文含本机标识

#### Scenario: 导出文件不含同步设置

- **WHEN** 用户在「我的」页导出备份
- **THEN** 下载文件仍只含原有备份信封
- **AND** 文件不含同步地址或本机标识

### Requirement: 失败不破坏本地，且允许之后重试

自动同步失败（无网络、超时或接收服务拒绝）时，系统 MUST 保持沉默，MUST NOT 挡住打卡、导入或导出，MUST NOT 修改已保存的打卡数据，MUST NOT 把这次失败记成成功。之后再次打开或回到前台时，系统 MUST 可以再试。

#### Scenario: 断网后仍可打卡

- **WHEN** 同步请求失败，用户继续完成本地打卡
- **THEN** 打卡结果保存在本机
- **AND** 今天仍算尚未成功同步

#### Scenario: 失败后下次打开会再试

- **WHEN** 上一次同步失败，用户稍后再打开应用
- **THEN** 系统再次尝试上传
- **AND** 只有这次成功才记为今日已同步

### Requirement: 用户可以改地址并手动同步

「我的」页 MUST 允许保存或清空同步地址。保存后的地址 MUST 覆盖默认地址。用户手动同步时：若今天尚未成功，系统 MUST 立即尝试一次；若今天已经成功，系统 MUST NOT 再发请求，并提示今天已经同步。手动失败 MUST 给出简短提示，且 MUST NOT 修改打卡数据。

#### Scenario: 保存地址后按该地址上传

- **WHEN** 用户在「我的」页保存一个新的同步地址并手动同步
- **THEN** 请求发往该地址
- **AND** 不再使用之前的默认地址

#### Scenario: 今天已成功时手动同步不再请求

- **WHEN** 今天已经成功同步，用户再次手动同步
- **THEN** 系统不发请求
- **AND** 提示今天已经同步

#### Scenario: 手动同步失败可以马上再试

- **WHEN** 用户手动同步失败
- **THEN** 系统给出简短失败提示
- **AND** 打卡数据不变
- **AND** 用户可以再次手动同步

### Requirement: 接收服务按本机标识保存最新快照

接收服务 MUST 接受 `POST /api/sync` 与 `PUT /api/sync` 的 JSON 正文。正文 MUST 含本机标识、模式版本、导出时间和领域数据。校验通过后，服务 MUST 按本机标识覆盖保存最新快照和接收时间，MUST 追加一条日志，并 MUST 覆盖写入最新一条记录。校验失败时 MUST 拒绝且 MUST NOT 覆盖该标识已有的快照。原型期响应 MUST 允许任意来源的跨域访问，从而包含 GitHub Pages 站点。服务 MUST 提供读取最新一条记录，以及按本机标识读取当前快照的方式。

#### Scenario: 合法备份被保存

- **WHEN** 接收服务收到一份含本机标识的合法备份
- **THEN** 该标识下保存这份快照和接收时间
- **AND** 日志增加一行
- **AND** 最新记录变为这一份

#### Scenario: 非法正文被拒绝

- **WHEN** 正文不是合法备份，或缺少本机标识
- **THEN** 服务拒绝该请求
- **AND** 已保存的快照保持不变

#### Scenario: 可以读回快照

- **WHEN** 某本机标识已有快照
- **THEN** 可以读到该标识的最新快照
- **AND** 可以读到最近一次成功接收的记录
